# Manuscript Tables

Working title: *An Interactive, Multilingual Statistical Decision Tree Linking Method Selection to jamovi, R, Assumption Checks, and Scientific Reporting*

Snapshot date: 17 August 2026. The website is under active development, so counts and coverage should be updated immediately before submission.

## Table 1. Components of the Statistical Decision Tree and their educational purpose

| Component | What the user does or receives | Educational or methodological purpose | Reproducibility contribution |
|---|---|---|---|
| Guided decision path | Answers sequential questions about the analytical goal, variables, measurement level, study design, dependence, distributional conditions, and other method-specific features | Converts an initially broad research problem into explicit methodological decisions and makes the reasoning behind a recommendation visible | The selected answers remain visible as a path that can be revisited and discussed |
| Direct test search | Searches by procedure name and selects from suggestions; the corresponding decision path is reconstructed automatically | Supports users who already know a possible procedure while still showing which data and design conditions would justify it | Makes a search-based choice auditable against the same decision logic as a guided choice |
| Recommendation and rationale | Receives a named analysis and a short explanation of why it fits the selected conditions | Connects the recommendation to the research question instead of presenting a procedure as a decontextualized command | Supplies a concise justification that can be checked against the study protocol |
| Expandable assumption guidance | Opens a detailed explanation for each assumption or prerequisite | Moves beyond assumption labels by explaining what each condition means, how it can be checked, and what may be considered when it is doubtful | Provides a reviewed assumption record for every recommendation endpoint |
| Psychology and sport-science scenarios | Reads one applied example from each domain | Helps learners transfer abstract design terminology to realistic research questions | Gives instructors and users reusable cases for teaching and verification |
| Downloadable example dataset | Downloads a prepared CSV file for the selected analysis | Enables immediate practice with correctly structured variables | Connects the same data to the jamovi and R workflows |
| jamovi procedure | Follows menu and module instructions tailored to the recommended analysis | Reduces the gap between choosing a method and locating it in a graphical statistical environment | Records the intended software route, including required jamovi modules |
| jamovi screenshot | Inspects a screenshot of the corresponding analysis setup or output when available | Provides visual orientation and helps users check variable placement and requested options | Offers a visual reference tied to the procedure and example data |
| R procedure | Receives concise R code and can consult the accompanying R Markdown compendium | Introduces a scriptable alternative and supports progression from graphical to reproducible analysis | Makes package use, model specification, and analysis commands inspectable and rerunnable |
| Effect-size guidance | Receives a commonly used effect-size measure and an interpretation note or range | Encourages attention to magnitude and uncertainty in addition to null-hypothesis significance testing | Prompts consistent extraction and reporting of an effect estimate |
| APA-style reporting example | Receives a model sentence containing the statistics normally needed for the selected procedure | Scaffolds transparent results writing and helps students connect software output to a scientific article | Functions as a checklist for statistics that should be retained from the output |
| Multilingual interface | Uses the tool in English, German, French, Spanish, or Italian | Reduces language barriers while preserving a shared methodological structure | Keeps decision logic constant while localizing questions, procedures, assumptions, and reporting guidance |
| Static overview PDFs | Opens compact tree diagrams for the principal routes | Supports teaching, printing, rapid orientation, and discussion of the overall architecture | Provides a versioned visual representation of the decision structure |

*Note.* The tool is educational decision support, not an automated substitute for statistical expertise, design-specific reasoning, or preregistration. “APA-style” denotes a reporting scaffold; users must adapt it to the study, journal, and actual software output.

## Table 2. Analysis families represented in the current decision tree

| Main route or family | Main decision criteria | Representative recommendations currently covered | Implementation support |
|---|---|---|---|
| Associations between variables | Number and measurement level of variables; linearity or monotonicity; independence; nominal versus metric data | Pearson, Spearman, and Kendall correlations; chi-square test of independence; log-linear model | Example data, jamovi route, R code, assumptions, effect size, and reporting scaffold |
| One-sample location and variance | Metric or ordinal outcome; known population standard deviation; distribution or symmetry; hypothesized variance | One-sample z test, one-sample t test, one-sample Wilcoxon signed-rank test, chi-square test for one variance | Example data or summary inputs, software procedures, assumptions, effect size, and reporting scaffold |
| Two-sample and paired comparisons | Independent versus paired observations; outcome scale; distributional conditions; target of comparison | Independent- and paired-samples t tests, Mann-Whitney U test, Wilcoxon signed-rank test, F test for two variances | Example data, jamovi and R procedures, assumptions, effect size, and reporting scaffold |
| Frequencies, proportions, and categorical outcomes | One versus multiple samples; theoretical versus empirical distribution; independence; expected counts; paired binary data | Binomial test, one-dimensional Pearson chi-square test, chi-square test of independence, Fisher exact test, McNemar test | Includes residual or post-hoc guidance where relevant and manual effect-size calculation notes where jamovi does not provide them |
| ANOVA and covariance models | Number of factors; independent versus repeated observations; covariates; outcome dimensionality; parametric conditions | One-way, factorial, repeated-measures, and factorial repeated-measures ANOVA; aligned-rank alternatives; ANCOVA; MANOVA; MANCOVA | Example data, menu-specific jamovi instructions, R models, assumptions, effect sizes, and reporting scaffolds |
| Regression and classification models | Outcome scale; number and type of predictors; prediction versus explanation; clustered observations | Linear, binary logistic, and multinomial logistic regression; discriminant analysis | Example data, jamovi and R procedures, diagnostics, effect sizes or performance measures, and cautions against unsupported causal interpretation |
| Mixed models | Continuous, binary, categorical, count, or ordinal outcome; repeated, nested, or clustered structure; random effects | Linear mixed model, generalized linear mixed model, ordinal mixed model | Example clustered data, jamovi module routes, R model syntax, assumptions, variance-explained measures, and reporting scaffolds |
| Latent-variable and causal-model routes | Observed versus latent variables; exploratory versus confirmatory aim; theoretically directed paths | Path analysis and mediation, confirmatory factor analysis, structural equation modeling | jamovi module guidance, R syntax, example data, model-fit assumptions, effect or path summaries, and causal-design cautions |
| Exploratory structure discovery | Correlation or distance information; goal of reducing variables, grouping cases, or representing proximity | Exploratory factor analysis, principal component analysis, cluster analysis, multidimensional scaling, network analysis | Example data, specialist jamovi modules, R workflows, interpretability and stability checks |
| Supervised machine learning | Known outcome; regression versus classification; interpretability and nonlinearity; train/test strategy | Decision tree, random forest, and k-nearest-neighbor regression; decision tree, random forest, k-nearest-neighbor, and naive Bayes classification | Example training data, SnowCluster or other jamovi module routes where available, R workflows, validation guidance, and performance reporting |
| Meta-analysis | Available study-level summary data; common versus varying effects; moderators; small-study effects | Meta-analysis of odds ratios, correlations, mean differences from n/M/SD, precomputed effect sizes, and proportions; fixed- and random-effects models; subgroup analysis; meta-regression; publication-bias diagnostics | Example study-level datasets, MAJOR routes in jamovi, metafor code in R, heterogeneity guidance, and reporting scaffolds |

*Note.* The current code contains 43 distinct recommendation identifiers. Some identifiers support more than one closely related terminal route, and some families contain optional follow-up analyses. Coverage should therefore be described by analysis family and recommendation endpoint rather than as a claim to include every possible statistical method.

## Table 3. Quality-assurance and verification framework

| Quality domain | Current procedure or evidence | Current status | Recommended evidence to archive for publication |
|---|---|---|---|
| Decision-logic consistency | Each terminal recommendation is linked to explicit answers in the tree; search selections reconstruct the same path | Implemented; continuing review as branches are added | Machine-readable list of nodes, answers, and terminal recommendations; independently reviewed path scenarios |
| Statistical assumptions | English assumption statements were exported to a 243-row review table, revised, approved, expanded into explanatory text, and translated | Content review completed for the current snapshot | Reviewed CSV with reviewer initials/date, references used for disputed assumptions, and version hash |
| Cross-language parity | English, German, French, Spanish, and Italian share the same node and result identifiers; translated assumptions and procedures are stored separately where needed | Implemented; linguistic polishing remains an ongoing task | Automated missing-key report plus native-speaker review for each language |
| jamovi procedure accuracy | Menu paths and module names have been revised iteratively against the installed jamovi interfaces and author-generated outputs | Broadly implemented; vulnerable to changes in jamovi or modules | Record jamovi and module versions; retain one verified `.omv` file and dated screenshot per endpoint where feasible |
| Screenshot-to-test matching | Screenshot filenames are mapped to recommendation identifiers and displayed for all interface languages | Implemented for available screenshots; coverage incomplete | Automated orphan/missing/multiple-match report and a screenshot inventory with verification date |
| Example-dataset suitability | Prepared CSV files are linked to endpoints and have been iteratively revised when software exposed coding or assumption problems | Implemented for most routes; statistical validation should be rerun before release | Data dictionary, expected result, assumption checks, and a script that confirms variable types and key outputs |
| R workflow reproducibility | A single R Markdown project contains package-installation checks, short purposes, and code for the represented analyses | Implemented; should be rerendered after dataset or package changes | Clean-session render log, `sessionInfo()`, package lockfile, and archived HTML/PDF output |
| Reporting guidance | Each result can display an APA-style example and the statistics normally reported for that method | Implemented as educational scaffolding | Method-specific checklist reviewed against APA/JARS and specialist reporting guidance; examples generated from verified outputs |
| Effect-size guidance | Each endpoint has a common effect or performance measure and an interpretation note; manual calculations are explained where needed | Implemented; conventions vary across fields | Citation for every threshold, explicit warning where no universal threshold exists, and confidence-interval guidance |
| Front-end behavior and accessibility | Responsive interface, keyboard-usable controls, visible focus states, back/reset controls, search suggestions, and modal assumption details | Implemented; formal audit not yet documented | Automated accessibility scan, keyboard test protocol, and desktop/mobile browser matrix |
| User-centered evaluation | Iterative author testing and informal feedback have shaped terminology, navigation, procedures, datasets, and visual design | Formative only | Preregistered usability study with representative students and researchers; task accuracy, completion time, SUS/UMUX-LITE, and qualitative feedback |
| Versioning and transparency | Source is maintained in GitHub; the site displays beta status and last-update information | Implemented | Tagged release, archived DOI, changelog, license, contribution policy, and reproducible deployment record |

*Note.* “Implemented” means present in the current development version, not externally validated. The distinction between content verification, software testing, and empirical usability evaluation should remain explicit in the manuscript.

## Search and coding method for Table 4 and Table S1

This was a targeted scoping search rather than a systematic review. Searches were run on 17 August 2026 using combinations of: `"which statistical test" flowchart`, `"choosing a statistical test" decision tree`, `"statistical test selection" flowchart`, `site:.edu statistical test decision tree`, `site:.ac.uk choosing statistical test pdf`, and related title/author searches. Peer-reviewed records were checked against PubMed, PMC, DOI landing pages, or institutional repositories. University and publisher resources were checked on their official pages. Citation chaining started from Suner et al. (2015), who had manually compared ten earlier decision trees when developing StatXFinder.

Resources were included when they explicitly mapped research-question, data, or design characteristics to statistical procedures. Generic textbooks without an identifiable selection aid, isolated calculators, AI-generated pages without stable provenance, reposts, and decision trees about machine-learning algorithms rather than statistical-method selection were excluded. Features were coded from publicly accessible text and figures. Because web resources change, all online comparisons require a final verification immediately before submission.
